# Investigación y publicación

## Fuentes y afirmaciones

- La fuente de verdad preferida es el repositorio original del proyecto y su código o documentación oficial. Registra la versión, etiqueta o commit consultado y la ruta concreta del archivo.
- Si no existe una fuente primaria accesible, se puede usar una fuente comunitaria solo si identifica un artefacto verificable, como la versión extraída, el archivo, la fecha o el método. Etiqueta claramente esa procedencia y no la atribuyas al fabricante.
- No inventes prompts, citas, versiones, commits, hashes, métricas, capacidades ni referencias. No completes fragmentos ausentes mediante reconstrucciones presentadas como evidencia.
- Si no se encuentra evidencia suficiente, indica «no localizado» o «no verificado» y explica qué se pudo comprobar. No publiques una muestra de prompt ficticia.
- Distingue siempre el prompt interno del agente de ejemplos de documentación, prompts suministrados por usuarios, plantillas auxiliares, instrucciones de subagentes y texto añadido dinámicamente por el runtime.
- Toda afirmación técnica relevante debe enlazar a la fuente que la respalda. Señala fecha de consulta y límites de la evidencia cuando puedan afectar a su vigencia o interpretación.
- Para comparar tecnologías, registra lenguajes a partir del repositorio/código y expón una razón de elección solo si el proyecto la declara explícitamente. Todo tamaño debe identificar versión, SO, arquitectura y formato; separa el tamaño comprimido del artefacto, el tamaño instalado y el del ejecutable.
- Para métricas volátiles como estrellas de GitHub, enlaza el repositorio y registra la fecha de captura; no las presentes como medidas de calidad.
