LA TESIS
01 / 05

No existe una proporción universal para el modelo, el prompt o el harness. El comportamiento surge de su interacción con el contexto, las herramientas y los permisos.

01 — Desmontar el agente

Cinco capas.
Un comportamiento.

Pulsa cada pieza. Una sola modificación puede cambiar el resultado.

01 / Modelo

El LLM propone texto o llamadas estructuradas. No ejecuta por sí mismo el shell ni tiene acceso automático al repositorio.

Dónde se origina la diferencia

Tres palancas.
Distinto control.

Una instrucción no crea una capacidad. Una capacidad tampoco concede permisos.

◉A / CAPACIDAD

El modelo propone

Interpreta la petición, selecciona pasos y genera código condicionado por sus pesos y la entrada.

Modelo: razonamiento y generación ante una entrada concreta.
✳B / INSTRUCCIÓN

El prompt orienta

Explicita rol, prioridades, límites y formato. Puede cambiar por modo, configuración y tools disponibles.

Prompt: lo que se pide y las restricciones que se expresan.
⌘C / EJECUCIÓN

El harness decide

Construye contexto, despacha acciones, aplica permisos, maneja errores y decide cuándo terminar.

Harness: qué acciones ocurren y qué feedback vuelve.
02 — Delegación y comunicación

Delegar no es
abrir otro chat.

La coordinación es un protocolo: el principal formula el trabajo, decide qué contexto transferir, asigna tools y recibe una salida que todavía debe integrar y validar.

Clave: dos agentes solo se comunican directamente si el runtime define un canal de mensajes. En muchos sistemas el subagente entrega al principal y no conversa con el usuario.
01 / Brief El principal transmite tarea delimitada, interfaces y criterio de finalización.

Transferencia de contexto

El controller empaqueta historial, archivos, interfaces, restricciones y presupuesto. Enviar más no siempre aporta más.

Canal de comunicación

Puede ser llamada con brief/respuesta, mensajes entre agentes o estado compartido. Si el host no lo implementa, no existe.

Supervisión e integración

El principal detecta conflictos, revisa cambios, ejecuta verificación y responde. Delegar no delega la responsabilidad.

Subagentes propios.
Protocolos compartidos.

La tabla muestra las 74 fichas, pero solo atribuye capacidades cuando hay evidencia enlazada; «no localizado» no significa «no soportado». 03B — Implementación y distribución

Lenguajes.
Artefactos medibles.

El lenguaje se toma del repositorio; el tamaño solo se compara cuando coinciden versión, plataforma y tipo de artefacto. La razón de diseño se marca como no localizada si el proyecto no la explica explícitamente.

Los tamaños son descargas Linux x86_64, salvo donde se indica npm o ejecutable sin comprimir. MB usa unidades decimales. No equivalen al tamaño instalado ni al consumo de memoria.

05 — Lo que el modelo lee

Prompts con
procedencia visible.

Abre «Ver prompt» en cada ficha para leer la muestra, el nivel de evidencia, la versión o condición conocida y el enlace al origen.

Cómo leer las etiquetas A = código oficial; B = ejemplo/documentación oficial (no necesariamente prompt por defecto); C = extracción comunitaria no validada por el proveedor; D = reconstrucción editorial; E = el prompt oficial no se ha localizado. Las citas son fragmentos breves, no el prompt completo.
Una muestra no equivale al prompt efectivo. Puede ser una plantilla auxiliar, un rol delegado o una instrucción con variables; el runtime añade contexto, herramientas y reglas del proyecto. Los productos cerrados no se rellenan con texto inventado: cuando no hay evidencia, el popup lo dice.

07 — Caso de estudio · Superpowers

La skill aporta método.
El host, ejecución.

Superpowers enseña diseño, planes, TDD, debugging y revisión. No es modelo ni runtime: depende de que el host pueda invocar subagentes y controlar un workspace.

La skill demuestra el procedimiento prescrito, no que todos los hosts lo ejecuten igual ni que mejore métricas.
